# Tejas Salon — v1

A full-stack salon website: public marketing site, customer accounts, appointment booking
(3 preferred slots + WhatsApp click-to-chat confirmation), a product store with cart/orders,
and an admin panel behind a captcha-protected login.

## Stack

- **Frontend**: Next.js 14 (App Router, TypeScript, Tailwind CSS) — `frontend/`
- **Backend**: Node.js, Express, TypeScript, Prisma, MongoDB (Atlas) — `backend/`
- **Auth**: Mobile number + password, JWT in an httpOnly cookie. Admin login additionally
  requires a captcha (a built-in math challenge by default — no third-party signup needed).

## Local setup

### 1. Backend

```bash
cd backend
cp .env.example .env   # then edit DATABASE_URL below
npm install
npm run prisma:push    # syncs collections + indexes to your MongoDB cluster
npm run prisma:seed    # seeds services, products, and a default admin
npm run dev             # http://localhost:4000
```

`DATABASE_URL` in `.env.example` is pre-filled with your Atlas connection string
(`mongodb+srv://keerthanak:<db_password>@cluster0.t7fpc.mongodb.net/tejas_salon?...`) — open
`backend/.env` and replace `<db_password>` with your real Atlas password (never paste the real
password anywhere it could get committed; `.env` is already gitignored). Also confirm in Atlas
that your current IP is allow-listed under Network Access, otherwise the connection will time out.

Seeded admin login: mobile `9999999999`, password `ChangeMe123!` — **change this immediately**
via the database or by wiring up a password-change endpoint before going live.

Prisma's MongoDB connector needs the cluster to be a replica set — Atlas clusters already are,
so this only matters if you ever point `DATABASE_URL` at a local MongoDB instead: run it with
`--replSet` and call `rs.initiate()` once.

### 2. Frontend

```bash
cd frontend
cp .env.local.example .env.local
npm install
npm run dev                 # http://localhost:3000
```

The frontend expects the backend on `http://localhost:4000` (see `NEXT_PUBLIC_API_URL`). If you
run the backend on a different port/host, update `.env.local` and `backend/.env`'s
`FRONTEND_ORIGIN` to match (CORS is locked to that one origin).

## What's implemented

- Public site: hero, "Our Craft" services grid, story section, looping gallery, team, product
  catalog, feedback wall + submission, enquiry/support form, map + contact, footer.
- Customer accounts: mobile + password login, 2-step onboarding (create password → pick service
  interests as multi-select cards).
- Booking flow (`/book`): requires login → pick services → pick 3 preferred date/time slots
  (9 AM–11 PM, custom calendar) → submit → celebration screen → optional WhatsApp click-to-chat
  link prefilled with the booking details, sent to `SALON_WHATSAPP_NUMBER`.
- Logged-in customer pages: `/history` (appointments + orders), `/cart` (product cart + checkout,
  pay-at-salon — no online payment gateway is wired up).
- Admin (`/admin` → `/admin/dashboard`): captcha-gated login, appointment status management,
  enquiries, feedback moderation (approve before it appears on the public site), and orders.
- SEO: server-rendered pages, per-page metadata, OpenGraph tags, `HairSalon` JSON-LD, sitemap.xml
  and robots.txt.

## Images

`frontend/public/images/*.svg` are on-brand placeholder graphics (gold/cream/navy) generated by
`frontend/scripts/generate-placeholders.mjs` — regenerate them with
`npm run generate:placeholders` if you tweak the palette. Replace individual files with real
photography whenever you have it; filenames are referenced directly in the components
(`components/Hero.tsx`, `components/Gallery.tsx`, `components/Team.tsx`, `prisma/seed.ts` for
services/products, etc.) so a same-name swap is all that's needed.

## WhatsApp

v1 uses **click-to-chat** (`wa.me` links) — zero setup, but a staff member has to send the
confirmation manually from the salon's WhatsApp. Set `SALON_WHATSAPP_NUMBER` (backend) and
`NEXT_PUBLIC_SALON_WHATSAPP_NUMBER` (frontend) to the salon's WhatsApp number in international
format with no `+` or spaces (e.g. `919876543210`).

To automate confirmations later, swap this for the official WhatsApp Cloud API (free, but needs
Meta Business verification) or Twilio's WhatsApp API (paid per message, faster to set up) — the
booking endpoint (`backend/src/routes/appointments.ts`) is the one place to change.

## Admin captcha

Defaults to a dependency-free math challenge (`backend/src/lib/captcha.ts`). To switch to
hCaptcha instead: sign up free at hcaptcha.com, set `HCAPTCHA_SECRET` in `backend/.env`, and wire
up the hCaptcha widget script + site key on `frontend/app/admin/page.tsx` (the backend already
branches on `HCAPTCHA_ENABLED` and verifies server-side).
